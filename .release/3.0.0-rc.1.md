# PlexonRanks 3.0.0-rc.1

Phase 2 premium progression release candidate. **Runtime certification on PlexonCraft remains pending; this release must remain a prerelease and the Phase 2 PR must remain draft/unmerged.**

## Candidate scope

- validated single-root/single-terminal progression graph with optional explicit `next` edges;
- deterministic presentation-tier inference without changing the existing ordered ladder requirements;
- premium `/rank` dashboard and paginated `/rank path` / `/ranks` progression view;
- SQLite schema 2 with non-empty pre-3.0 migration backup and asynchronous bounded history;
- authoritative SQLite rank state with LuckPerms as PlexonRanks-owned persistent permission/group projection;
- compare-and-set rank-up and administrative mutations with compensating rollback;
- 30-second admin confirmations bound to actor, target, exact action/value, expected authoritative rank and active configuration generation;
- reward preflight, no item world-drop overflow, reversible rewards before the irreversible external-command boundary;
- immutable 3.0 API views while preserving deprecated 2.x accessors;
- cached PlaceholderAPI aliases and max-rank/readiness presentation;
- transactional reload validation including configured LuckPerms group references;
- Java 25 / Paper 26.2 distribution checks and dependency-isolation verification.

## Authority and irreversible boundary

PlexonRanks' SQLite state is authoritative. LuckPerms is reconciled as a managed projection and unrelated LuckPerms nodes are not removed.

Arbitrary console-command rewards cannot be generically rolled back. They execute only after all reliably reversible stages have passed. If an external command fails after crossing that boundary, PlexonRanks records `EXTERNAL_REWARD_FAILED`, does not automatically replay the command sequence, and keeps the advanced authoritative rank to avoid duplicate external rewards.

## Migration

Read `docs/MIGRATION_3.0.0.md` before staging. A 2.2.1 schema-1 database is backed up to `<database>.pre-3.0.bak` before schema 2 is committed. Existing player rank IDs are preserved; unknown IDs follow the explicitly configured missing-rank policy rather than being silently remapped.
